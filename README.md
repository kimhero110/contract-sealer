# 合同盖章工具（contract-sealer）

> 月底 30 份合同要盖章，你打开 PS，三小时后手腕抽筋、血压拉满、骑缝章还切歪了两份。
> 这个工具就是为了终结这种日子而生的。

把公章"盖"到扫描版合同（PDF / 图片）上的本地桌面小工具。**盖出来的章和真章一样大**——
打印出来拿尺子量，误差不超过 1mm。还能一键盖骑缝章、附上手写签名、补一个落款日期，
每次的章迹都带一点随机手感，不会假得像复制粘贴。

全程离线运行，不联网、不上传、不偷看你的合同——它连网卡都懒得理。

## 三件难事

**物理尺寸 1:1。** 导入印章时录入真实直径（公章一般 40/42mm），之后每一枚章打印出来都分毫不差。
扫描件歪歪扭扭、手机拍照带黑边？程序先用 OpenCV 自动框出纸面，你拖四个角微调一下，
透视拉正为标准 A4，物理基准就回来了。

**骑缝章。** 印章按页数切成竖条（宽度随机，更像真的），每页贴一条在纸边上，拼回去又是一枚完整的章——
**数学上保证能拼回去**，不是玄学。左侧开口也支持，页序会自动镜像。盖之前有拼合预览让你先验货；
页数太多切得太细，它会直接拒绝你，而不是让你拿着 0.4mm 的红线去丢人。

**随机手感。** 角度、色度、蒙尘、切片宽度全都带小幅度随机，由种子驱动，每次导出的章迹都是绝版。
种子会记进输出文件旁的 `.sealog`，想复现随时能复现。

还有落款日期（Ctrl+D，字高填 4.5mm 打印量到就是 4.5mm）和手写签名（白纸上签个名拍进来，
自动抠图入库，能存成"末页落款套餐"模板）。

都是 Windows 版，不需要装 Python。

上手流程：打开合同 → 右侧"导入图片…"喂一张印章照片（自动抠图）→ 填真实尺寸 →
"盖到当前页" → 拖到落款处 → Ctrl+E 导出。原件一根汗毛都不会动，导出的永远是新文件。

## 源码运行与开发

```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m app.main

.venv\Scripts\python.exe -m pytest tests -q   # 全绿才算完
.venv\Scripts\ruff check .                    # 同样要全绿
.venv\Scripts\mypy                            # 类型检查，CI 也跑
```

月底 30 份合同不想一份份点？先在界面里把章导好、模板存好，然后交给命令行：

```bat
.venv\Scripts\python.exe -m core.cli list                                   # 看看有哪些章和模板
.venv\Scripts\python.exe -m core.cli batch --template 末页落款 --out D:\out ^
    --perforation 公章 合同1.pdf 合同2.pdf 合同3.pdf                        # 套模板 + 骑缝章，逐份导出
```

导出默认 JPEG 质量 92（300DPI 下肉眼看不出）；原件是文字页或还要过 OCR，
在「文件 → 导出设置」里换成无损 PNG（命令行 `--png`），代价是文件大好几倍。

架构一句话：UI 层（`app/`）只说"毫米"，core 层（`core/`）干所有像素换算的脏活累活，
全部算法可脱离 GUI 测试；会话与导出/批量也在 core，命令行和界面共用同一份。没装 PySide6 的机器（比如纯 Linux CI）上 GUI 用例自动 skip，
core 层测试照跑——CI 里单独有一个"无 Qt"job 就是为了守住这条分层。

真正难的地方不在"把图贴到 PDF 上"，在于一些看上去已经做对、实际上错了的地方：
骑缝章的两种几何模型互相矛盾、左开口页序没镜像而拼合预览替它圆谎、Qt 与 PIL 的旋转正方向相反……
都记在 **[设计决策](docs/设计决策.md)** 里，每条都写了现象、根因和定论。
动工前的原始方案存档在 [项目方案](docs/项目方案.md)，逐版变更见 [CHANGELOG](CHANGELOG.md)。

## 严肃三秒钟（法律与安全）

- 本工具仅供**本单位已授权印章**的内部流程使用。拿它伪造印章或签名是**犯罪**，不要干，干了也别说认识我。
- 图片印章不是《电子签名法》意义上的可靠电子签名，**不具备与实体印章同等的法律效力**。
  需要法律效力的场景请用有资质的电子签章服务。
- 印章库存放在你本机的 `%APPDATA%\contract-sealer\seals\`（macOS/Linux 下分别在
  `~/Library/Application Support` 和 `$XDG_CONFIG_HOME`）。那是你的公章，请像对待真章一样对待这个文件夹。
- 导出的 PDF 默认压平：印章不再是可以单独拖出来的图层对象。**这不等于"提取不了"**——
  任何人都能把整页图裁出印章。压平防的是顺手一拖就复用，不是防专业人士。
- 导出件是整页位图，原件里可选中、可搜索的文字不再是文字。需要保留文字层请另想办法。
- **授权：本项目以 [GNU AGPL-3.0](LICENSE) 发布。** 依赖 PyMuPDF 同为 AGPL，
  触发条件是**分发**而不是卖钱：只要你把程序（含 exe）给到本组织之外，就必须一并提供对应源码并沿用 AGPL。

## 已知限制

- 双骑缝（左右开弓）、程序生成印章：还在愿望清单上躺着；
- 骑缝章要"换手感"需重新打开骑缝章对话框，切片也不支持单片「重盖」；
- 自动纸边检测靠纸/背景亮度差。无边扫描件会框住整幅图（这是对的）；实在框不出来时给一个默认框让你拖；
- 中文日期格式需要系统装有中文字体，没有会明确报错并建议换纯数字格式，**不会**给你画一排豆腐块；
- 蒙尘手感的"像真程度"取决于印泥物理学造诣，欢迎提 Issue 交流盖章心得。
