# 设计决策

这个工具真正难的地方不在"把图贴到 PDF 上"，在于一些看上去已经做对、实际上错了的地方。
下面每条都是开发中真实踩过的：**现象是什么、根因在哪、最后怎么定的**。
按踩坑顺序排，不按重要性。

---

## 1. 骑缝章有两种几何模型，而方案里同时写了两种

初版方案里同时出现了"印章切成 N 条竖片、每片完整落在页内"和"印章圆心压在纸边线上、
半个章悬到纸外"两种描述，各自都自洽，合起来互相矛盾。这种矛盾不会在编译期暴露，
只会在某一页的切片位置上体现为一两毫米的偏差，等打印出来对不上才发现。

**定论：只保留切片平铺。** 每条切片完整落在页面内，贴齐开口侧纸边（内缩 inset），
N 页切片横向平移拼接后还原完整印章。"半章悬出纸外"被砍掉的理由很硬：
纸外的像素导出即被裁掉，对拼合验证没有任何贡献。

一个方案里允许存在两种几何模型，等于没有模型。

## 2. 左开口骑缝章的页序必须镜像，而拼合预览会替它圆谎

右开口的映射很直觉：页码升序 = 切片从左到右。左开口时位置做了镜像，页序却沿用了同一条映射，
结果扇开拼出来的印文左右颠倒。

正确的定义要从**验章动作**倒推：按住一侧把文件扇开，从左到右读露出来的页边条——
右开口时越靠后的页露得越靠右，从左到右是页 1…N；左开口时越靠后的页露得越靠左，
从左到右是页 N…1，所以页 i 必须承载第 (N+1-i) 条切片。

真正危险的是第二层：**拼合预览原先按页序排切片**。左开口时页序与切片序相反，
预览显示的是一张左右颠倒的印文——而用户恰恰是拿这张图去确认"拼得回去"的。
预览自己说了谎，这个 bug 就永远不会被发现。

**定论：** 切片带自己的 `slice_order`（在印章内的左起序号），拼合预览按它排，不按页序排。
验证工具的正确性优先于被验证对象。

## 3. 旋转的正方向，Qt 和 PIL 是反的

画布用 `QGraphicsItem.setRotation`，正角度=顺时针；导出用 `PIL.Image.rotate`，正角度=逆时针。
用户在预览里把签名拧正 θ，导出时净误差是 **2θ**——拧 90° 的结果是倒立。

**定论：全系统 `rotation_deg` 一律以 Qt 语义为准（顺时针为正），导出侧取负适配 PIL。**
`test_rotation_direction.py` 用一个不对称的箭头图守着这条约定：对称图形测不出方向错误，
这正是这类 bug 能活很久的原因。

## 4. 逐页旋转抖动会悄悄破坏宽度守恒

骑缝章的可拼合性靠一条不变量：各切片宽度之和恒等于印章总宽。为了像真章，每片加了 ±1° 的独立抖动。
`PIL.rotate(expand=True)` 会把切片撑宽到 `|w·cosθ| + |h·sinθ|`——40mm 章切 5 页、抖动 1°，
每片多出约 0.7mm，不变量在默认参数下就已经失效了。

**定论：** 旋转后居中裁回配额宽度（`_rotate_keep_width`），并补了 20 个种子的守恒回归测试。
教训不是"别用 expand=True"，是**任何加在数据上的效果都要回过头检查它有没有破坏已声明的不变量**。

## 5. 四点校准：从"点四下"改成"拖把手"

原实现是依次点击四个角。三个问题叠在一起让它几乎不可用：

1. **点了就定死。** 四个点没有任何调整手段，错一个角只能 Esc 从头再来；
2. **单击即落点。** 鼠标点击自带一两像素抖动，而放大镜是六倍——用户在放大镜里
   看到准星没对准的那一刻，点已经落下去了。缺的是"按下→拖动→松开"这个微调窗口；
3. **能缩放不能平移。** 取点期间 `dragMode` 被设成 `NoDrag`，滚轮缩放却没被拦。
   放大到能看清纸角、点下第一个角之后，根本挪不到第二个角，只能缩小回去，精度白给。

**定论：改为拖把手模型**，逐条对上：初值由自动纸边检测给出（检测不到就给页面内缩框），
用户永远不从零开始；四个角随时可改；拖动天然是按下→拖→松开；沿用画布原本的
`ScrollHandDrag`——拖把手是调整，拖空白处是平移。

两条随之而来的不变量：把手半径按**屏幕像素**恒定（场景单位是毫米，不补偿的话放大 10 倍
时把手会变成盖住半张纸的圆饼）；范围钳制用 `ItemPositionChange` 在移动**之前**改写目标位置，
而不是移动之后 `setPos` 拉回——后者会让 `itemChange` 递归自触发。

顺带修掉一个视觉误导：旧版连线按点击顺序画，按对角顺序点四下会画出一个交叉的蝴蝶形，
看着像出错了，其实结果是对的。

## 6. 确认动作只有快捷键，等于没有出口

拖把手模型上线后，确认仍然只认回车、取消只认 Esc。两个毛病：快捷键只写在右侧信息栏，
画布上没有任何可点的东西；更要命的是回车要送到画布的 `keyPressEvent`，
前提是画布持有键盘焦点——用户中途点过右侧面板或工具栏，焦点就走了，
回车按下去毫无反应，看上去像程序卡死。

**定论：** 画布底部加浮动确认条（`app/confirmbar.py`），按钮设 `NoFocus`——
点它不抢画布焦点，点完还能接着用方向键微调把手。回车与 Esc 照旧可用，与按钮共用同一条代码路径。

## 7. 按钮文字被省略，根因不在文案长度

窗口没最大化时，右侧面板的按钮显示成"↻ 重盖选…"。第一反应是文案太长，
把"单行四按钮"改成"2×2 网格"只是把症状推后了一点。

**根因：`QPushButton` 没有重写 `minimumSizeHint`。** `QWidget` 的默认实现返回无效尺寸，
布局据此认为按钮的宽度下限是 0——面板一被挤窄，按钮先于其他控件让位，文字先挨刀。

**定论：** `FitButton` 把 `minimumSizeHint` 钉在 `sizeHint` 上（重写方法而不是构造时
`setMinimumWidth`——后者在 QSS 生效前取值会漏掉 padding）。这个下限会沿布局链一路上报给
`QSplitter`，面板既拖不窄，窗口也自然算得出自己的最小尺寸，不必再拍脑袋写死。

一个反直觉的配套细节：右侧面板**不能**调 `setMinimumWidth`——显式最小宽度会盖掉
`minimumSizeHint`，反而可能被压到比内容还窄。同理，普通 `QScrollArea` 会把内容的宽度需求
整个吞掉（那本来就是它的用途），所以竖向滚动用的是重写了 `minimumSizeHint` 的 `VScrollArea`。

## 8. 撤销栈：逆操作闭包换成快照命令栈

最初每个动作自己写一个"逆操作"闭包。漏一个字段就静默出错，而且天生做不了重做。
四点校准那条逆操作里还引用了一个尚未赋值的局部变量，导致每次点完四个角必定崩。

**定论：** 改为快照式命令栈，撤销与重做共用同一份前/后状态，动作中途失败整体回滚。
那个必崩的 `UnboundLocalError` 不是被"修好"的，是随着整段逆操作闭包的消失而不复存在——
**能让一类 bug 无处可藏的重构，胜过修掉其中一只**。

还有一条教训级细节：撤销只改记录，**画布重建必须跳过"画布→记录"回同步**，
否则旧贴图位置会把刚撤销的记录覆盖回去。这与另一个"差集剪除误删记录"的 bug 同源，
问题都是：画布和记录，谁是真相源。

## 9. 缓存键用 `id()`，删页之后会串图

页面 LRU 缓存原先以 `id(page)` 为键。删页后对象被回收，CPython 会复用同一个地址，
新页面于是拿到旧页面的缓存图。

**定论：** `Page.uid` 单调自增作为缓存键。**`id()` 只在对象存活期间唯一，不是身份。**

## 10. 压平导出防得了什么，防不了什么

README 曾写"印章无法被从中提取"。这是过度承诺。

**事实：** 压平消除的是 PDF 里可分离的图层对象，防的是"顺手一拖就复用"，
**不防任何人把整页图裁出印章**。同时它有代价：导出件是整页位图，原件里可选中、
可搜索的文字在导出件中不再是文字。

**定论：** 两条都写进 README。安全承诺写宽一格，比功能少一个更伤信任。

## 11. 去噪阈值按整图面积算，小数字就成了噪点

抠图去噪的连通域阈值曾是"整张图片面积的 0.05%"。素材是手机照片时，这个数字
随像素总量水涨船高：12MP 照片里一枚 800px 的章，阈值 6000 像素，而印文底部编号
里一个数字只有一两百像素——13 个数字整排被当噪点扔掉。再加一道 3×3 开运算，
小尺寸素材上 ≤2px 宽的笔画整条消失。用户看到的是"偶发丢几个小数字"：
同一枚章，拍得近就没事，拍得远就丢。

**定论：阈值只能相对墨迹自身的尺度。** 先用大块连通域估计墨迹外接尺寸 D，
面积 ≥ (D×0.5%)² 且落在外接范围内的才保留；开运算取消，单像素噪点由面积下限兜住。
回归测试用合成章验证 13 个数字一个不少。

**照片的像素总数不是尺度，墨迹的尺寸才是。**任何"相对整图"的阈值都在赌输入分辨率。

## 12. 会话模型不能长在主窗口里

导出、批量、模板、骑缝章记录都写在 `MainWindow` 里时，批量盖章只能借用
交互式加载路径：把每份文件依次"打开"到界面上、套模板、导出、最后清空。
界面状态成了批处理的中间态，批量一跑当前文档就没了；想加个命令行入口也无从下手。

**定论：** 文档 + 记录 + 随机器收进 `core.session.Session`，落章/模板/骑缝/渲染/导出
全部在它上面；主窗口只翻译用户动作并画画布；批量是 `batch_stamp(job)`，
界面和命令行调的是同一个函数。**界面里看到的和命令行批出来的，必须是同一份算法。**

## 13. 跨线程信号直连 lambda，槽在工作线程里跑

导出挪到工作线程后，第一版把工作线程的信号直接 `connect` 到 lambda。
Qt 对没有 QObject 接收方的连接只能"直连"——槽在**发射方线程**执行，
于是进度对话框在工作线程里被改、主线程的事件循环在工作线程里被 quit，测试直接卡死。

**定论：** 接收端是一个住在主线程的 QObject（`app/worker.py` 的 `_Receiver`），
连接显式 `QueuedConnection`。**跨线程只传信号，不传对象；谁的线程谁动手。**

## 一句话架构

UI 层（`app/`）只说毫米，core 层（`core/`）干所有像素换算的脏活累活，
全部算法可脱离 GUI 测试；会话（文档 + 记录 + 导出/批量）也在 core，
命令行 `python -m core.cli` 与界面共用它。CI 里那个"不装 Qt 的 Linux 测试 job"就是这条分层的守门人——
它跑不起来，说明算法又爬回界面层去了。

测试素材是程序生成的**合成**图片（`tests/fixtures/generate_fixtures.py`），真章永不入库；
图片本身也不入库，`tests/conftest.py` 在缺失时自动生成——可生成物不是源码。
